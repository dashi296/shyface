# Maestro E2E テスト実装プラン

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Maestro フローファイル（YAML）を `e2e/flows/` に作成し、iOS シミュレーターで 5 本の Happy Path E2E テストを手動実行できる状態にする。

**Architecture:** サブフロー `subflows/register_person_a.yaml` で人物登録操作を共通化し、それを必要とするフローが `runFlow` で呼び出す。全フローは `launchApp: clearState: true` で DB をクリアして独立性を確保する。

**Tech Stack:** [Maestro CLI](https://maestro.mobile.dev/) / iOS Simulator / expo-image-picker (PHPickerViewController) / React Native TouchableOpacity（`disabled` prop → `accessibilityState.disabled`）

---

## 前提・制約（実装前に必ず確認）

| 項目 | 内容 |
|---|---|
| Bundle ID（開発ビルド） | `com.dashi296.shyface.dev` |
| 開発サーバー起動コマンド | `EAS_BUILD_PROFILE=development bunx expo run:ios` |
| フィクスチャ注入 | `bun run e2e:setup`（シミュレーター起動済みが前提） |
| フォトピッカーの "Add" ボタン | **英語ロケール**を前提。日本語ロケールのシミュレーターでは `"追加"` に変更が必要 |
| 写真選択の座標 | iPhone 15 Pro（393×852 pt）を前提。他デバイスでは調整が必要 |
| カメラシナリオ | iOS Simulator では不可のため対象外 |
| モザイク視覚検証 | Maestro はピクセル比較非対応のため対象外 |

## Task 2: サブフロー `register_person_a.yaml` を作成する

**Files:**
- Create: `e2e/flows/subflows/register_person_a.yaml`

このサブフローは「起動済みアプリの人物管理タブに移動し、Person A を登録して一覧に表示するまで」の操作を担う。呼び出し元フローが `launchApp` 済みの状態で使う。

**前提知識:**
- `RegisterFaceSheet` は Step1（form）→ Step2（photos）→ Step3（confirm）の 3 ステップ構成
- 名前 TextInput のプレースホルダー: `"例: 山田 太郎"`
- Step2 のヒントテキスト: `"顔写真を 3 枚追加してください（0/3）"` → 3枚選択後: `"（3/3）"`
- 写真ピッカー: `allowsMultipleSelection: true`、最大 3 枚。iOS PHPickerViewController を使用
- 写真選択確認ボタン: 英語ロケールでは `"Add"`（日本語: `"追加"`）

- [ ] **Step 1: `register_person_a.yaml` を作成する**

`e2e/flows/subflows/register_person_a.yaml` を以下の内容で作成する。
サブフローファイルは `appId` ヘッダー不要（呼び出し元から継承）。

```yaml
# サブフロー: person_a を登録する
# 前提: launchApp 済み・アプリが任意の画面に表示されている
# 事後: 人物管理画面に "Person A" が表示されている

- tapOn: "人物管理"
- assertVisible: "登録人物"

# FAB をタップして登録シートを開く
- tapOn: "＋"
- assertVisible: "人物を登録"
- assertVisible: "名前 *"

# Step1: 名前入力
- tapOn: "例: 山田 太郎"
- inputText: "Person A"
- tapOn: "次へ"

# Step2: 写真選択
- assertVisible: "写真を追加"
- assertVisible: "顔写真を 3 枚追加してください（0/3）"
- tapOn: "ライブラリ"
- waitForAnimationToEnd

# iOS Photos ピッカー（PHPickerViewController）
# 3列グリッドの1行目から3枚選択
# 座標: iPhone 15 Pro (393x852 pt) 基準
# 再調整が必要な場合は point の値を変更する
- tapOn:
    point: "17%, 27%"
- tapOn:
    point: "50%, 27%"
- tapOn:
    point: "83%, 27%"

# 選択確定（英語ロケール: "Add"、日本語ロケール: "追加"）
- tapOn: "Add"
- waitForAnimationToEnd

# Step2 に戻り 3枚揃ったことを確認
- assertVisible: "（3/3）"
- tapOn: "確認へ"

# Step3: 確認画面
- assertVisible: "確認"
- assertVisible: "Person A"
- tapOn: "登録する"
- waitForAnimationToEnd

# 登録完了: 人物一覧に表示される
```

## Task 4: `02_person_registration.yaml` を作成する

**Files:**
- Create: `e2e/flows/02_person_registration.yaml`

**テスト対象シナリオ:**
- FAB タップで登録シートが開く
- 名前未入力時は "次へ" が無効（`accessibilityState.disabled = true`）
- 名前入力後に "次へ" が有効になる
- Step1 → Step2 → Step3 の遷移
- 写真3枚選択で "確認へ" が有効になる
- 登録完了後に人物一覧に表示される
- キャンセルでシートが閉じる

**前提知識:**
- `Button` コンポーネントは `disabled` prop を `TouchableOpacity` に渡す → `accessibilityState.disabled` が設定される
- Maestro の `assertVisible: { text: "...", enabled: false }` でこれを検証できる
- キャンセルボタンのテキスト: `"キャンセル"` （シートヘッダーの右上）

- [ ] **Step 1: `02_person_registration.yaml` を作成する**

```yaml
appId: com.dashi296.shyface.dev
---
- launchApp:
    clearState: true
- tapOn: "人物管理"

# FAB で登録シートを開く
- tapOn: "＋"
- assertVisible: "人物を登録"
- assertVisible: "名前 *"

# 名前未入力時は "次へ" が無効
- assertVisible:
    text: "次へ"
    enabled: false

# 名前を入力すると "次へ" が有効になる
- tapOn: "例: 山田 太郎"
- inputText: "Test Person"
- assertVisible:
    text: "次へ"
    enabled: true
- tapOn: "次へ"

# Step2: 写真追加画面
- assertVisible: "写真を追加"
- assertVisible: "顔写真を 3 枚追加してください（0/3）"

# 写真3枚選択前は "確認へ" が無効
- assertVisible:
    text: "確認へ"
    enabled: false

# ライブラリから写真を選択
- tapOn: "ライブラリ"
- waitForAnimationToEnd
- tapOn:
    point: "17%, 27%"
- tapOn:
    point: "50%, 27%"
- tapOn:
    point: "83%, 27%"
- tapOn: "Add"
- waitForAnimationToEnd

# 3枚揃うと "確認へ" が有効になる
- assertVisible: "顔写真を 3 枚追加してください（3/3）"
- assertVisible:
    text: "確認へ"
    enabled: true
- tapOn: "確認へ"

# Step3: 確認画面
- assertVisible: "確認"
- assertVisible: "Test Person"
- tapOn: "登録する"
- waitForAnimationToEnd

# 登録完了後: 人物一覧に表示される
- assertVisible: "Test Person"

# 再度シートを開いてキャンセルしてもリセットされる
- tapOn: "＋"
- assertVisible: "人物を登録"
- tapOn: "キャンセル"
- assertNotVisible: "人物を登録"
```

## Task 5: `03_person_management.yaml` を作成する

**前提知識:**
- 空状態テキスト: `"登録された人物がいません"` / `"右下のボタンから人物を登録してください"`
- 削除ボタンテキスト: `"削除"`
- Alert タイトル: `"削除確認"` / メッセージ: `"「Person A」を削除しますか？"`
- Alert ボタン: `"キャンセル"` / `"削除"`

- [ ] **Step 1: `03_person_management.yaml` を作成する**

```yaml
appId: com.dashi296.shyface.dev
---
- launchApp:
    clearState: true
- tapOn: "人物管理"

# 未登録時の空状態
- assertVisible: "登録された人物がいません"
- assertVisible: "右下のボタンから人物を登録してください"

# person_a を登録
- runFlow: subflows/register_person_a.yaml

# 人物一覧に表示される
- assertVisible: "Person A"
- assertNotVisible: "登録された人物がいません"

# 削除ボタンをタップ → 確認ダイアログ
- tapOn: "削除"
- assertVisible: "削除確認"
- assertVisible: "「Person A」を削除しますか？"

# キャンセルすると人物が残る
- tapOn: "キャンセル"
- assertVisible: "Person A"

- assertVisible: "削除確認"

    index: 1
- waitForAnimationToEnd

# 削除後: 一覧から消え、空状態に戻る
- assertNotVisible: "Person A"
- assertVisible: "登録された人物がいません"
```

**注意:** Alert に「削除」ボタンが2つ存在するケースを避けるため、`index: 1` で2番目の「削除」（Alert のボタン）を選択する。もし `index` が効かない場合は Maestro の `tapOn: { text: "削除", index: 1 }` ではなく、Alert ボタンの accessibility ID を確認する。

## Task 7: `05_debug.yaml` を作成する

**Files:**
- Create: `e2e/flows/05_debug.yaml`

**テスト対象シナリオ:**
- Debug タブが表示される（開発ビルドのみ）
- 閾値・パディングの調整行が表示される
- "＋" で値が増加する
- "−" で値が減少する
- "すべてデフォルトに戻す" でリセットされる

**前提知識:**
- `FACE_SIMILARITY_THRESHOLD = 0.7` → 初期表示: `"0.70"`
- `FACE_CROP_PADDING = 0.1` → 初期表示: `"0.10"`
- `THRESHOLD_STEP = 0.05` → "＋" 1回で `"0.75"`
- `PADDING_STEP = 0.05` → "＋" 1回で `"0.15"`
- "＋" / "−" / "戻す" は各行に存在するため、`index` で区別する
- 値が override 状態（デフォルト以外）のとき青色で表示され、"戻す" ボタンが有効になる
- `ValueRow` コンポーネントはラベル・デフォルト値テキスト・現在値・ボタン群を持つ

- [ ] **Step 1: `05_debug.yaml` を作成する**

対処: `"Add"` を `"追加"` に変更する

### 写真ピッカーの座標タップが失敗する

原因: デバイスサイズ・OS バージョンによるグリッドレイアウトの差異  
対処: `maestro studio` を起動してインタラクティブに座標を確認する

```bash
maestro studio
```

### `launchApp: clearState: true` でアプリが起動しない

原因: 開発ビルドが未インストール  
対処: `EAS_BUILD_PROFILE=development bunx expo run:ios` でビルド・インストールする

### `enabled: false` の assertVisible が失敗する

原因: RN の `TouchableOpacity` の `disabled` が Maestro の accessibility ツリーに反映されていない  
対処: 該当行をコメントアウトし、代わりに「タップしても Step が変わらない」ことで確認する

```yaml
# 代替: 名前未入力時に "次へ" をタップしても Step2 に遷移しない
- tapOn: "次へ"
- assertVisible: "人物を登録"  # まだ Step1 のタイトルが見える
```
